### 架构落点（记住这些判据，别再重推）

  （events/renderer/coordinate/assets/adapter/scenes/loop），第二个实例当场抛错；
  `stage()` 同名重复也抛错。目前只有 `adapter.connect` 做成 stage（可能失败的才配 stage）。
- **唯一切换出口**：`SceneDirector.switchTo`（切换锁 + 1s 内同目标 >4 次判循环 +
  `SCENE_TRANSITIONS` 拒绝非法边）。`world→world` 是最好用的「非法切换」测试用例。
- **单一权威状态**：只有 `GameAdapter` 读 `Dn`。P6 源码里出现 `Dn.x =` 直接被 p6.test.mjs 判死。
- **城市管理是覆盖层不是场景**：原版 `ka()` 协程横跨「选城→菜单→指令→回选城」，
  切独立场景会切断协程；所以 `cityIsOverlay=true`，只登记开合 + 保存/恢复地图表现。

### 存档（原版事实，写死记）
- 头 `[83,71,66,51]`="SGB3"、版本 4；key = `jn(slot)` = `sgby.sango${2*slot}.sav` 与 `+1.sav`；
  base 片 `35+19*200+2*200+2*33 = 4301 B`，dyn 片 `2035+37*38 = 3441 B`。

### 踩坑（这轮花了最多时间的三个）
1. **`saveManager.load()` 之后 `GameAdapter.sync()` 必须 `force`**：读档后数据签名可能不变
   （读的还是同一档），普通同步会被 EventManager 60ms 去重窗口吞掉 → 3D 层停在旧表现。
   实现用 `forcedSyncs` 生成 epoch 后缀当 dedupeKey。
2. **`UIStack` 必须引用计数**：同 id 重复入栈若只保留一条，`close(t2)` 会提前把 `blocking`
   置 false → 嵌套弹窗时输入被提前放行（表现为「弹窗还能点地图」）。
3. **`getInputPhase().kind === 'zs'` 不等于「玩家在城市阶段」**：`wa()`（指令处理）里也有 `zs()`
   （选目标），此时 P3 的 `cityLoop=false`，点城市只走路不开界面。唯一可靠判据是
   `__P3__.getStatus().cityLoop === true && kind==='zs'`。同理，判断「战斗结束回到可操作」也要看 `cityLoop`。

### 原版回合规则（自动化对局的坑，不是缺陷）
- 战斗结束后原版要走完「战报(`Ms`) → `wa()` → `Ma()` 回合菜单 → 下一回合 `ka()`」，
  期间会给 10+ 次 `zs()` 等待。自动化只能：点掉 `.p3-modal`、补确认键 39、等到 `cityLoop=true`。
- **本月已行动的城**被选中会弹一次提示后**回到选城**（不进 `ei()/$r()`，`declines` 仍为 0）——
  smoke 里表现为「点了城但界面不开」。正解是**换一座己方城**（脚本用候选表 + 最多 5 轮、要求 ≥2 轮成功）。
- 如果 `p3Status().p3city` 一直是旧城号、`dlgOpen=0`、`modal=0`，说明选城被原版**静默拒绝**
  （非玩家回合 / 该城不可选），不要去查 P6。

### 测试工程经验
- `node --test tests/`（传目录）会 `MODULE_NOT_FOUND`，必须**逐文件跑**。
- 无头 smoke 里「等界面开」不能只 `waitFor`：原版提示框会卡住流程，等待循环里要**顺手点掉对话框**。
- P6 覆盖层登记是 400ms 低频比对，读 `director.cityOverlay` 前要 `sleep(700~800)`，
  否则会测出「刚开还没登记」的假失败。
- 自检会污染运行统计（`claim` 冲突自检会让 `duplicates++` 导致面板假告警），自检前后要**保存/还原**。

### 本轮实测抓到的 6 个真缺陷（都不是"看代码"看出来的）
1. **`gl.getExtension()` 在上下文丢失后按规范返回 null** → `restoreContext()` 永远拿不到扩展对象。
   正解：上下文健康时（装配阶段）先把 `WEBGL_lose_context` 取到并缓存。凡"丢失后再取扩展"的写法都是错的。
2. **自适应分辨率把 `_syncDevicePixelRatio()` 排在 warmup 判断之后** → 窗口拖到 HiDPI 屏后预热期内
   仍按旧像素比渲染。dpr 变化是环境事实，不是"决策"，必须排在 warmup 之前。
3. **长跑基线在 `perf.attach()` 取**（场景还没装配，geo=0）→ 面板显示 `Geo +10 / Tex +40 / 堆 +54MB`，
   把"装配"误报成"泄漏"。正解：装配完成时 `rebaseline()`（只重设资源/堆基线，不动帧统计）。
4. **帧时间统计用钳位后的 `dt`**（`Math.min(0.1, …)` 是给模拟用的）→ 出现"CPU 耗时 71.5ms > 平均帧时间"
   的物理不可能数字。正解：帧钩子多传一个**未钳位** `rawMs`；`dt` 继续钳位。
5. 工具栏 chip 中文竖排成 4 行（缺 `white-space: nowrap`）；`start.bat` 文案还停在 P3。
6. **一致性探针把 `u.index` 写成 `u.slot`** → `Dn.g_GenPos[undefined]` 恒空 → 坐标比对整段被
   `continue` 跳过，**全绿但一条没比**。教训：探针里任何 `if (!x) continue` 都要能统计"跳过多少条"。

### 测试断言的三个经典错误（写断言比写功能更容易骗自己）
- `!!document.getElementById('p6-fatal')` 恒为真——致命面板容器 mount 时就常驻 DOM，只能用
  `ui.getStatus().fatal`（可见性）判断。
- `renderer.getSize()` 返回的是 **CSS 逻辑尺寸**，不是后备缓冲；验证高 DPI 必须看 `canvas.width/height`
  （实测 1600×900@dpr2 → 3200×1800）。
- 状态指纹里不能混 `fps`/`drawCalls` 这类随时间变化的量，否则渲染抖动会被判成"状态被改了"。

### 环境事实（写报告时要复用的口径）
- 本机只有 Edge 156（无 Chrome）→ Chrome 只能标"未实测"；SwiftShader 是软件光栅化，
  **FPS 绝对值不代表真实显卡**，只做同环境前后对比；GPU 时间/显存不可测（有 `EXT_disjoint_timer_query` 但未使用）。
- 测试期 `/sw.js` 404 是脚手架 `SGBY_NO_SW=1` 故意为之（原版内核自己注册 SW），不是发布缺陷。
