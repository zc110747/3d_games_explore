## P6：默认 2D 主界面 + 正面俯视 + 3D 操作对齐原版（commit f994c2b）

### 做了什么
1. **视图两态**：`body[data-sango-view]` = `menu`（原版 2D 整屏，默认）/ `game`（3D + HUD）。
   判据 `GameAdapter.getInputPhase().kind`：`zs|ei|battle` → 3D，`menu` → 2D，`unknown` 保持。
   `p6/ViewMode.mjs` 每 180ms 轮询；切 game 时 `resume+resize+战略相机复位+城市/旗帜全量同步`，切 menu 时渲染一帧后 `pause`。
2. **俯视相机**：`CAMERA_CONFIG` 0°/90°；`CameraManager._applyDirection` 在俯角 ≥89.5° 用 `up=(0,0,-1)`（否则 up 与视线平行、lookAt 退化）；旗帜改水平旗布（`rotation.x=-π/2`，飘动改 `rotation.z`）。
   整图取景 `margin 1.3 + offsetY -0.1`；平移边界改成动态 `max(0, 地图半幅 − 视野半幅)`，整图可见时拖不出画面。
3. **操作对齐 zs()**：点格 → `requestCursorTo()` 逐格投递方向键；再点同格 → `pressKey(39)`。
   键盘不拦截（原版自己 `window keydown` 消费 WASD/E/Q/Tab/M），底部按钮条只投 38/51/34-37/39/40。

### 踩到的坑（可复用）
- **`kind` 判不出来会切错画面**：战斗中 `waitMsg` 栈落进 `menu` 规则 → 画面被切回 2D、3D 装载卡在 `entering`。
  修法两层：① 战斗函数名（`Uo|UoOrig|bo|ko|vo|xo|Ao|Fo|Io|Eo|So`）也判 `battle`；② `ViewMode.guardGame`（P4 active）优先级高于 kind。
- **`applyView(game)` 会 `switchTo(world)`**：战斗中被视图抖动触发一次就把 battle 场景切走，`onReady` 静默 `return`，phase 永久停在 entering。加 `inBattle` 保护。
- **俯视下 panLimit 9/7 会把地图拖出视野**：斜视 frustum 大看不出来，俯视 fit 后一拖就空屏（城市投影到 -1000px）。必须动态收敛。
- **`--window-size` ≠ 实际 innerHeight**：headless Edge 给 1080x650，原版整数倍缩放按它算；靠 CDP `setDeviceMetricsOverride` 改尺寸会打断原版主菜单的开局按键节奏（12 次确认仍 year=0），必须在启动参数里定尺寸。
- **测试用例断言口径要一致**：`CityUIAdapter.officerIds()`（队列人数）≠ `getCityOfficers().rows`（ss() 过滤后可操作），城市界面重开还可能落到另一座城 → 用界面当前 `cityId` 取期望值。

### ⚠️ `.wm-overlay` 在页面里有**两个**
原版「菜单」面板 + 一个隐藏的「云存档同步」面板，同 class。
`document.querySelector('.wm-overlay .wm-close')` 会点到隐藏的那个 → 表现为"菜单关不掉、之后点击全被吃"。
必须 `[...querySelectorAll('.wm-overlay')].find(o => o.classList.contains('open'))`，
且关闭要用**真实鼠标**点（`wm-close` 依赖 pointerdown 才触发 peek 退出逻辑）。

### ⚠️ 静默失败：`RoadRenderer` 的 THREE 未定义（最值得记的一条）
`highlightNeighbors()` 里写裸 `THREE`，但该模块约定 THREE **由构造函数注入**（`this.THREE`），
`build()` 里用 `const THREE = this.THREE` 做别名，这个方法漏了 → `ReferenceError`，一次回归触发 11 次。
**测试全绿却功能全坏**，原因两重：
- smoke 只在**启动时**查一次 `exceptions.length===0`，交互期异常只打印不判定；
- `getDiagnostics().highlighted` 只数 `links` 里的边数，**根本不看 `_highlight` Mesh 是否存在**。
修法：补别名 + `getDiagnostics()` 加 `highlightMesh`/`highlightVertices` + smoke 加"高亮真的生成了 Mesh"
与"全程无页面 JS 异常"两条断言。
→ **通则：凡是"算逻辑 + 画东西"两段式的功能，断言必须落在渲染产物上（Mesh 存在 / 顶点数 > 0）。**

### ⚠️ 性能口径：本机 20fps 是天花板，不是代码问题
- 无头 Edge 158 + SwiftShader + 1570×758：idleWorld 20.56 / stress 19.56 / dpr2 19.83 fps，draws 91 tris 17178。
- 三条独立证据：`busyShare 0.96%`（CPU 每帧 0.468ms，帧间隔 p50 恰好 50.0ms = 20fps 整数节拍）；
  独立 rAF 探针暂停时 60fps、运行时 20fps；隐藏全部 3D 对象仍 23fps、像素比 0.5 仍 21fps。
- 同机测 P7 旧代码 `62ae442` = 19.45fps → 合并后 20.56fps，**无回归**。
- **P7 报告的 59.67fps 作废**：那是 1240×610 且页面停在 2D、3D 已 `pause()` 时测的（等于一帧没画）。
  perf 脚本已改：测量前 `__P6__.setView('game', true)` 钉住 3D，并打印应用内 frameStats 交叉校验。
- `dropRate 0.984 / slowFrames 1169` 也不能当回归指标：判据以 16.67ms 为基准，20fps 环境必然全判慢帧。
  smoke 长跑改为相对衰减 `>= 长跑前×0.8 && >= 12fps`。
- 自适应像素比确实会动作（dpr2 时 cap `2→1.5→1`，理由 `p95 100ms > 22ms 严重降两档`）。
