## 1. 运行方式

```bash
# ① 启动（原版方式不变）
cd original
node server/server.mjs              # 或双击 start.bat（端口 8787，占用自动顺延）

# 原版 2D 入口（完全不变）
#   http://127.0.0.1:8787/
# P1 3D 架构入口（新增）
#   http://127.0.0.1:8787/index3d.html
```

`index3d.html` 放在 `site/` 根目录，保证 `assets/game.zip`、`assets/fontbm*.bin`、`config.json`、`sw.js` 等相对路径与原版一致；页面保留原版 DOM（`#screen` / `#status-bar` / `#touch-controls` / `#menu-btn`），因此 `sgby.core.js` 与 `local-bridge.js` 均可正常启动。

```bash
# ② 重新生成内核桥接（原版 sgby.min.js 更新后必做）
node tools/make_core.mjs
node --check original/site/sgby.core.js

# ③ 测试
node --test tests/coordinate.test.mjs tests/adapter.test.mjs tests/architecture.test.mjs
node tests/smoke.mjs
```

`tests/smoke.mjs` 会自动起一个独立服务（端口 8791，`SGBY_NO_SW=1`），用本机无头 Edge + CDP 真实等待页面自检完成，然后校验 DOM 状态、渲染器、场景切换、UI 阻断与窗口缩放，最后关闭服务。

## 3. 架构与数据流

```
sgby.core.js（原版逻辑，唯一权威）
   │ 只读导出 Dn / l / lib / 类 / 函数
   ▼
GameAdapter ──(输入边界 waitMsg / __SGBY_CTX / 500ms watchdog)──► EventManager
   │ 只读投影                                                        │
   ▼                                                                ▼
SceneManager ── WorldMapScene / CityScene / BattleScene ──────► Three.js 对象
   │                                                                ▲
   └────────── RenderManager（唯一 rAF：update + render）────────────┘
                        ▲
        InputManager（3D 画布） / HTML UI（data-p1-ui 层）
```

- **渲染循环不读游戏数据**：状态读取只发生在输入边界、`__SGBY_CTX` 变化、500ms 低频 watchdog 与手动 `sync()`。
- **事件不写游戏逻辑**：所有投影 `Object.freeze`，`Dn` 由适配层只读。
- **坐标分层**：`CoordinateSystem` 只做「逻辑格 ↔ 世界坐标」；`worldToScreen()` 接受注入的 projector（摄像机投影），两者不混用。
