# P5 交付说明 —— 战斗交互、操作流程与动画系统

> 阶段范围：把 **原版战斗协程**接到 3D 战棋操作上 —— 选部队 / 移动 / 攻击 / 待机 /
> 回合结束 / 战斗结束，以及对应的路径、动画、受击、死亡与战果表现。
>
> 铁律：**所有战斗规则仍由原版 ko()/vo()/xo()/Ao()/Fo()/Qo() 执行**，P5 只做
> 「把 3D 拾取翻译成原版输入」与「把原版结果翻译成表现」。
>
> 前置：P0 调研报告、P1 架构、P2 战略地图、P3 城市管理、P4 战斗地图。
> 本文行号指 P0 还原副本 `sgby.pretty.js`（由 `original/site/sgby.min.js` 词法还原）。

### 1.1 关键链路（全部真实源码）

```
Uo()  ── yo() 初始化 ── Io() 回合开始 ──┐
                                        │
   ┌────────────────────────────────────┴─────────────┐
   │ Eo() 我方阶段                                     │
   │   ko()   ← bo(mo)   点格子/部队（Xo 判定能否操作）│
   │    vo(t) ← bo(Co,Mo) 点目标格（Mo 校验可达并落点）│
   │    Ao(e) ← $r(vi(8)) 行动菜单：攻击/计谋/查看/待机 │
   │    xo(t,e,n) ← bo(Po) 点目标（_o/No 校验）        │
   │    Fo(e)  结算（伤害/兵力/状态/死亡/经验）        │
   └───────────────────────────────────────────────────┘
                                        │
                         So() 敌方 AI ── Ki() 粮草 ──┘
```

P5 的接入点只有两个：

1. **输入**：`bo()` 是战斗里**唯一**等待输入的地方（`await l.input.waitMsgTimeout(200)`）。
   P5 在 `bo()` 执行期间临时替换 `waitMsgTimeout`，把自己队列里的 `{type:16,...}` 消息
   喂给原版循环；`bo()` 退出时 `finally` 原样还原并清空队列。
2. **菜单**：`$r()` 在战斗中被 P5 接管（行动菜单 / 计谋列表 / 战斗菜单），
   条目文本直接来自原版实参，返回值仍是原版取值域（下标或 255）。

### 1.2 内核钩子（P5 新增 9 处改名 + 1 处 `$r` 分支）

`tools/make_core.mjs` 现在做 **18 处**唯一字符串改名（P3 七个控件 + P4 两个 + P5 九个）：

| 原名 | 改名后 | shim 行为 |
|---|---|---|
| `bo()` | `boOrig()` | 进入时通知宿主并临时替换 `waitMsgTimeout`；`finally` 还原 |
| `ko()` | `koOrig()` | 前后通知 `select` / `selectDone(unitId)` |
| `vo(t)` | `voOrig(t)` | 前后通知 `moveBegin` / `moveDone(unitId, result)` |
| `xo(t,e,n)` | `xoOrig()` | 前后通知 `targetBegin{type,param,unitId}` / `targetDone(result)` |
| `Ao(t)` | `AoOrig(t)` | 前后通知 `actionMenu(unitId)` / `actionDone{type,param,aIdx}` |
| `Fo(n)` | `FoOrig(n)` | 前后通知 `resolveBegin` / `resolveDone`（同一份出入参） |
| `Io()` | `IoOrig()` | `turnBegin` + `turnStart(Dn.g_FgtBoutCnt)` |
| `Eo()` / `So()` | `EoOrig()` / `SoOrig()` | `playerPhase`/`playerPhaseEnd`、`enemyPhase`/`enemyPhaseEnd` |

**没有任何 shim 修改判定、返回值或调用顺序**：9 个 shim 全都是
「通知一次 → `await *Orig(...)` → 通知一次 → 返回 *Orig 的原值」。

### 1.3 与 P4 的分工

- P4 `boot`：`enter / ready / exit` 三时刻的**场景装载、数据灌入、场景退出**。
- P5 `boot`：只在 P4 **装载成功**之后才注册 `window.__SGBY_P5_HOST__`。
  未注册时内核 shim 全部走 `*Orig`，即完全回到原版 2D 输入 ——
  这样「3D 装载失败」时战斗仍能在 2D 里打完，不会出现「3D 没画面、输入又被 3D 吃掉」。

### 1.4 「逻辑状态 vs 表现状态」的隔离方式

- 模型的**基准位置**永远来自 `GameAdapter`（= 原版 `g_GenPos` 的格子）；
- 动画只叠加 `dx/dy/dz/rotY/scale` 覆盖量（`BattleUnitRenderer.setVisual`），
  每帧位移按 `期望世界坐标 - 基准世界坐标` 重算，因此动画中途就算发生
  `syncAll()`（基准跳到终点）模型也不会跳变，仍在路径上；
- 动画结束、或场景退出、或战斗结束时 `clearVisual()` 一律把模型交还给逻辑位置。

### 3.2 GameAdapter（P5 操作通道）

| 接口 | 类型 | 说明 |
|---|---|---|
| `battleCellToScreen(x,y)` | read | 逻辑格 → 原版 240×320 像素（`(cell-视口原点)<<4` + 半格），并报 `inWindow` |
| `ensureBattleView(x,y)` | write | 格子不在 15×17 视口内时调用原版 `eo()` 滚动（`g_MapSX/SY` 为纯显示量） |
| `clickBattleCell(x,y)` | write | 投递 `type:16` 按下+抬起两条消息；**不判断合法性**，返回体不宣称成功 |
| `pressBattleKey(param)` | write | 投递一次原版键码 |
| `getBattleMenus()` | read | `vi(8)`/`vi(9)` 切分后的条目（4 项 / 5 项） |
| `getBattleUnitStates()` | read | 20 支队伍的紧凑快照（hp/mp/arms/state/active/x/y） |
| `getBattleOutcome()` | read | `g_FgtOver` 原文 + `meaning: win\|lose\|none` |
| `getBattlePathField()` | read | 当前 `g_FightPath` 225 字节 + 窗口原点（不重算） |
| `getCurrentAttackRange()` | read | 直接读 `g_FgtAtkRng`（`Ao` 调用 `Vo` 后的有效范围） |
| `getLastBattleMove()` | read | `g_BakUpX/Y`（移动前）与 `g_GenPos`（移动后） |

命令式 `moveUnit/attackUnit/endTurn` **仍是 `UnsupportedError`**（理由已更新为本阶段事实）。

## 6. 遗留问题

### 6.1 自动化对局未必然出现「我方主动攻击」

出征时粮草由出征方携带，**打几回合取决于粮草**（原版 `Ki()` 每回合扣减，`Io()` 判负）。
本次自动化对局的粮草在 2 回合内耗尽，原版按 `0===MProvender → g_FgtOver=2` 结束，
没有走到交战；另一次随机对局中曾出现 `resolves=6`（敌军主动进攻我方，`Fo` 链路真实跑通）。

因此：
- **接口与流程**（选目标 / `Vo` 范围 / `xo` 判定 / `Fo` 调用）已由真实对局验证；
- **动画与战果表现**（补间、命中、受击、死亡、差值、超时、取消）由 39 项 Node 断言确定性地覆盖；
- 想完整打一场「我方进攻获胜」，需要手动选粮草充足的战场：进入战斗后多打几回合，
  把部队推到城池格并结束该部队行动（`Fo` 返回城池地形 5 且 `Mode=1` → `g_FgtOver=1`）。

### 6.2 其他

1. **`M` 键（原版小地图 `na()`）仍会打开 2D 覆盖层**：它用 `gamDelay(50,2)` 读**真实队列**，
   P5 的虚拟队列不参与。此时按物理 Esc 即可退出（`class A` 的 window 监听仍然有效），
   3D 面板会在下一次 `bo()` 打开时恢复。未做拦截是为了不修改原版按键映射。
2. **`Ao` 菜单的「取消」语义与「待机」不同**：取消（`$r` 返回 255）会让 `Fo` 把部队
   退回移动前位置并清 `active`（原版行为，已在 P5 文档与代码注释中标注）。
3. **敌方阶段的「跟随动画」是补播**：AI 在 `Dn` 里瞬时完成位移，3D 逐段补间；
   玩家阶段开始时 `cancelAll` 直接对齐原版最终位置（不会出现长期不一致）。
4. **战果面板出现在战略地图之上**：原版 `Uo()` 返回后立即继续指令结算，
   战果只是叠加展示（9 秒后或点「关闭」消失），不参与任何流程。
5. **战斗内 2D 画面仍保留**：「原版画面」按钮仍可操作 2D，真实输入队列优先于虚拟队列。
6. **技能（计谋）路径未逐一实测**：菜单、`Ro()` 选计谋、`Vo(1,skill,id)` 9×9 范围都走同一套
   接管点；自动对局中没有出现可施放的计谋，属未覆盖而非未实现。
