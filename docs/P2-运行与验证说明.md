## 1. 结论摘要

P2 完成，**未进入 P3**。战略地图已能独立运行：原版 38 座城市、54 条真实连接、19 个势力值全部以只读投影驱动 3D 表现；地形底板直接使用**原版资源包里的 108 帧城市地图图块**，不是程序化虚构地形。

三个必须说明的真实结论：

1. **原版没有命令式 `selectCity()`**（P1 已如实标注 `UnsupportedError`）。P2 按真实源码把 3D 点击接回原版 `zs()` 输入循环：`GameAdapter.requestCitySelection()` 经 `class A.pushMsg()` 投递方向键/确认键，原版自己移动 `Dn.g_CityPos` 光标并决定后续。浏览器真机验证：脚本化开局（year=190、`kind=zs`）后，指向城 #1(9,0) 的请求投递 8 个方向键，原版光标确实变为 `(9,0) → 城 #1`。
2. **原版地形数据是完整的**。资源 54「城市地图图块」有 108 帧 32×32（12×9），`qs()` 用 `(t.y+row)*fn+col` 取帧；P2 用同一索引在运行时拼成整张底板贴图，并明确把顶点起伏/低面数山体标为**装饰性几何，不作为规则依据**。
3. **原版绘制网格与命中网格不一致**（P0 §3.3 遗留）。`qs()` 绘制用 20px 格 + OY=57，`zs()` 命中用 32px 格 + 底部 `Ks=269`；P2 的 `MapCoordinateSystem.logicalToOriginalScreen()` 按**命中公式**反推，取格内 1/4 处以避开 240px 边界，未修改原版代码。

## 2. 运行方式

```bash
cd original
node server/server.mjs
# 浏览器打开 http://127.0.0.1:8787/index3d.html
```

- 原版入口仍是 `/`（`index.html` → `sgby.min.js`），**14 个原版文件一个字节未改**。
- 3D 入口 `index3d.html` 加载 `sgby.core.js`（= `sgby.min.js` 逐字节前缀 + 1,060B 只读导出尾注）、`p1/main.mjs` 与 `p2/` 模块；importmap 指向本地 `p1/vendor/`，无 npm 运行时依赖、无构建步骤。
- 页面左侧「地图调试」面板可查看任意城市的 ID/名称/逻辑坐标/世界坐标/势力/连接数量，以及选中城与原版输入联动结果；工具栏「原版画面」可展开原版 2D 对照窗（默认收起，让 3D 地图完整可见）。

### 操作

| 操作 | 效果 |
|---|---|
| 左键拖动 | 沿相机 right/up 在地面的基向量平移（受 `panLimitX=9 / panLimitZ=7` 限制） |
| 滚轮 / `+` `-` | 以视口中心为锚点缩放（0.6～3，只改 `camera.zoom`，target 不变 → 无跳动） |
| 单击城市 | 表现层选中 + 高亮模型/名称/原版相邻路径；同时按原版输入协议请求 `zs()` 定位光标 |
| `R` | 相机复位 |
| 面板「原版联动」 | 切换 `cursor`（默认，仅定位原版光标） / `select`（追加确认键，会进入原版自身菜单） |


## 10. 遗留问题（未擅自改动规则）

1. **原版默认停在主菜单 `Ba()`**：未开局时 `getInputPhase().canSelectCity=false`，3D 点击只做表现层高亮并**如实标注「未注入原版输入」**，绝不伪造选城结果。进入剧本后链路可用（已实测）。
2. **`intent='select'` 会进入原版自身 `ei()` 城市菜单**（P3 才做 3D 菜单）。P2 默认 `intent='cursor'`，不打开任何菜单。
