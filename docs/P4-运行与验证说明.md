> 阶段范围：只做**战斗地图的 3D 表现 + 单位/范围可视化 + 拾取**。

### 1.1 关键链路（全部真实源码）

```
玩家在城市菜单选「军备→出征」(指令 27)
  → mi() case tn (L5311)：选将 Ls()、粮草 Js()→Hs()、目标城 zs()、hi() 算行程
  → ys() 写入原版指令队列 g_OrderQueue（OrderId=27）
  → 结束城市阶段：zs() 返回 255 → ka() 返回 → Ua() 调 Ma() 菜单（$r，2D）→ 选「继续」
  → wa() (L7213) 逐条处理指令 → _a() case tn (L7136)
       n = g_FgtParam.GenArray；MapId = 110+城市地图id-1；Way = 连接表里目标城的方向索引
       Mode=1（玩家进攻）或 0（玩家防守）；MProvender/EProvender 来自订单粮草与目标城粮草
  → await Uo()  ← ★ P4 钩子：enter → yo() → ready → 回合循环 → exit
```

`Uo()`（L6253）= `yo()`（初始化）→ `Io()`（回合开始、粮草结算、状态恢复）→
`Eo()`（我方，`ko()` 等输入）→ `So()`（敌方 AI）→ `Ki()`（粮草消耗）。

### 1.2 内核钩子（新增 2 处改名 + shim）

`tools/make_core.mjs` 在**生成副本**上做 9 处唯一字符串改名（P3 的 7 个控件 + P4 的 2 个）：

| 原名 | 改名后 | shim 行为 |
|---|---|---|
| `yo()` | `yoOrig()` | `await yoOrig()` 后通知宿主 `ready`（地图/编成/位置/移动力此时才就绪） |
| `Uo()` | `UoOrig()` | 进入通知 `enter`；`try { await UoOrig() } finally { 通知 exit }` |

shim **不改变返回值、不改变调用顺序、不写 Dn**；宿主异常被 `try/catch` 吞掉并打印，
因此「表现层挂了」不会影响原版战斗继续在 2D 跑。

生成器对每处断言「恰好命中 1 次」，并在自检里把 9 处改名**反向还原**后与 `sgby.min.js`
逐字节比对（`tests/p4.test.mjs` + `tests/smoke.mjs` 双份），确保业务代码零改写。

### 1.3 战斗数据读取口径

| 字段 | 来源 | 说明 |
|---|---|---|
| 地图宽高 | `Dn.g_MapWid/g_MapHgt` | `yo()` L5755 从 `Ci()[0]/[2]` 取；`yo()` 之前为 0，`getBattleMap()` 如实返回 `available:false` |
| 格子图块号 | `Ci()[16 + y*W + x]` | 直接对应图集帧号 0..45（7 张图实测值域 1..45） |
| 地形类别 | `Ui(x,y)`（L5411） | 0..7 = 草地/平原/山地/森林/村庄/城池/营寨/河流，短名取界面字符串 `[7]` |
| 部队槽位 | `g_GenPos[0..19]` + `g_FgtParam.GenArray[i]` | 0..9 我方、10..19 敌方；`GenArray` 值 = 武将编号+1，0 表示空槽 |
| 部队名称 | `$n(officerId)` | 原版查表（随时期） |
| 兵种名/状态名 | `lib.getStr(1, 12)` / `lib.getStr(1, 28+state)` | 与原版 `Oo()` L6282 的取值表达式一致 |
| 移动范围 | `qi(unitId)` → `g_FightPath[0..224]` | 可到达判据 = `0 < v < 128`，与原版 `ea()`（画移动范围，L6659）完全一致 |
| 攻击范围 | `Vo(0,0,unitId)` → `g_FgtAtkRng` | `[0]=边长, [1]/[2]=左上角, [3..]=掩码`；掩码 `===1` 与原版 `Ho()` L6620 一致 |
| 可操作判定 | `Xo()`（L6433） | 只扫 0..9；`state!==8 && active===0 && state!==1 && state!==6` 才可选 |

**不复制规则的三处细节**（都已写进代码注释）：

1. `getMovementRange/getAttackRange` 会写 `g_FightPath` 与 `g_FgtAtkRng` —— 它们是原版每帧重算的临时量，
   且 `zo()`（敌方自动反击 L6600）**直接复用** `g_FgtAtkRng`。因此调用前后做快照/还原，
   保证 2D 原版流程的战斗结果一字不差。
2. `canSelectUnit()` 复用原版 `Xo()`；因为它按「焦点格」判定的，这里临时把 `g_FoucsX/Y` 指向目标部队、
   **同步调用后立刻还原**，不复制判定条件、也不留下状态改动。
3. 地形高度、装饰体、颜色全部是表现层装饰（原版没有地形高度概念），不参与任何判定。

## 6. 遗留问题

1. **战斗操作仍在原版 2D**：3D 只做显示与选中。移动/攻击/待机/回合结束需要驱动
   `ko()→vo()→xo()→Ao()→Fo()` 这条输入链，属 P5。可用「原版画面」按钮查看与操作。
2. **退出路径的自动测试是「表现层接线」直测**：`core.p4.notify('exit')` 只验证
   「收到 exit → 收 HUD → 回战略地图」，不改游戏状态。真实结束战斗需要 2D 输入
   （全军撤退/打完），自动化成本高，未纳入。
3. **`canSelectUnit()` 临时借用 `g_FoucsX/Y`**：同步调用、立即还原，无残留；但严格说这是一次
   对原版临时量的写操作，已在代码注释与本表标注。
4. **天气/模式无文字名**：原版只有天气图标（资源 9）与 `Mode` 数值，HUD 如实显示数字，不编造名称。
5. **单位模型是程序化几何体 + 徽章**：未使用 GLB/正式美术（P4 §6.3/§7 允许）。徽章字取原版兵种名首字。
6. **`g_MapWid` 战斗结束后不清零**（原版行为）：`getBattleMap()` 会返回上一场地图；
   `invalidateBattleMap()` 与 `active` 状态已用于区分，但外部直接调用时需注意。
7. **地图缓存按 `mapId:宽x高:数据长度` 缓存**：同一场战斗内不会变；跨战斗靠 `invalidateBattleMap()`。
8. **「已行动」标记尚未经真实变化验证**：`active` 只在 `Io()`/行动后变化，P4 不驱动行动，
   实测恒为 0；标记已实现，但要等 P5 接管行动后才可能被真实触发。
