# P6 交付说明 —— 全局整合、场景切换与存档兼容

P6 把 P1～P5 合成为一个**可以直接从头玩到尾**的游戏：一个启动入口、一个渲染循环、一个场景
切换出口、一个权威数据源（原版 `Dn`）、一套存档（原版 `ac()`/`oc()`，格式不新增任何字段）。

本文件按任务书「十四、阶段交付物」的 8 项组织。全部数字来自真实运行，未通过的项目单独列出
原因（见 §8.1）。

### 1.2 改造点

- `main.mjs`：统一启动入口（`AppLifecycle`）+ P6 装配 + 存档面板 + 状态面板 6 行 P6 指标 +
  P6 自检 10 项 + `window.__P6__` 调试入口；`switchScene()` 改走 `SceneDirector`。
- `GameAdapter.sync({ force })`：读档后签名没变也必须**全量重派发**（`forcedSyncs` 生成 epoch
  后缀绕过事件去重窗口），否则 3D 层会停在读档前的旧表现。
- `CameraManager.setView()`：只改视图不改数据，供场景切换/读档恢复相机。
- `tools/make_core.mjs`：导出 `core.p6.save`（`jn/Jn/Hn/sc/ac/oc` + 头/版本）与
  `core.p6.capacity`（容量），**引用原版符号而不是复制格式**；生成物 220,154 B。

## 2. 全局架构说明（交付物 1）

### 2.1 游戏初始化流程

`boot()`（`original/site/p1/main.mjs`）是唯一入口，顺序固定：

| 序号 | 动作 | 守卫 |
| --- | --- | --- |
| 1 | 取 DOM 引用，构造 `AppLifecycle`（挂 `window.__SGBY_LIFECYCLE__`） | 同名 `stage` 重复执行会抛错 |
| 2 | 构造 `EventManager` / `CoordinateSystem` / `MapCoordinateSystem` / `CameraManager` / `WorldCamera` / `AssetManager` / `RenderManager` / `InputManager` | — |
| 3 | 校验 `window.__SGBY_CORE__`（缺失即抛错），构造 `GameAdapter` / `SceneManager` | 没有内核就不启动 |
| 4 | `lifecycle.claim()` 登记 7 个必须唯一的对象：`events / renderer / coordinate / assets / adapter / scenes / loop` | 第二个实例当场抛错 |
| 5 | 注册场景：`world`（`StrategicMapScene`）、`city`（`CityScene`，P6 不再进入） | 未注册的场景不能切换（`canSwitch` 报「未注册场景」） |
| 6 | `renderManager.setFrameCallback(update/render)` → `renderManager.start()` | 全项目只有这一个 `requestAnimationFrame` 循环 |
| 7 | `setState('connecting')` → `stage('adapter.connect')` 等原版 `game.zip` 解析完并安装钩子 | 15s 超时→启动失败 |
| 8 | P2（`MapInteraction` + `StrategicMapScene`）→ P3（`createCityManager`）→ P4（`createBattleManager`）→ P5（`createBattleOps`）→ P6（`createIntegration`） | 每个模块 import 时即冻结依赖，缺依赖构造即抛 `TypeError` |
| 9 | `setState('ready')` → 绑定存档面板 → 页面自检 → `setState('running')` | 自检失败只记录，不阻断游玩 |

初始化面板实测：`1 阶段 / 288~325ms / 唯一对象 events,renderer,coordinate,assets,adapter,scenes,loop / 重复 0`。
（P6 只把「等原版资源包」这种**可能失败**的阶段做成 `stage`，其余子系统用 `claim` 守卫唯一性 +
`getStatus()` 里逐个列出，避免为了好看而堆空 stage。）

### 2.2 场景管理结构

```
SceneManager (P1)  ── 只认 id / 工厂 / 生命周期
   ├─ world  : StrategicMapScene   3D 战略地图（38 城 / 旗帜 / 道路 / 选择）
   ├─ city   : CityScene           3D 城市场景（P6 场景表保留，实际不走：见 §3.1）
   └─ battle : BattleMapScene      P4 注册的 3D 战棋地图
SCENE_TRANSITIONS = { world:[city,battle], city:[world], battle:[world] }

SceneDirector (P6) ── 所有切换的唯一入口
   ├─ _switching 重入锁
   ├─ _checkLoop()  // 1s 内同目标 > 4 次判定「疑似无限循环」
   ├─ captureWorldState() / restoreWorldState()   // 只存相机与选中，不存游戏数据
   └─ _applyTransition()  // 战斗进出计数 + 退出时按最新 Dn 重建
```

每个 3D 场景都实现 `initialize / enter / update / render / exit / dispose`。
`exit()` 只退订与停动画，不销毁资源（同一实例会被复用）；`dispose()` 只在页面销毁时调用。

### 2.3 GameAdapter 数据访问结构

- 只有 `GameAdapter` 直接读 `window.__SGBY_CORE__.Dn`，其余模块**全部**经 adapter 取值。
- 写操作一律不改 `Dn`：走原版输入协议（`sendInput`）或原版业务函数（`ac/oc/qs`）。
- 提供 `sync({ source, force })`：按快照签名去重派发事件；`force` 时用 `forcedSyncs` 生成的
  epoch 后缀绕过 60ms 去重窗口（读档/重建必须用到）。
- `snapshotSignature()` 用于「读档前后数据是否真变了」的判定，不用于业务判断。

### 2.4 EventManager 事件结构

- 单一 `EventManager` 实例（`lifecycle.claim('events')`），所有订阅返回 `unsubscribe`。
- P6 订阅 6 类事件：`SCENE_CHANGED / GAME_STATE_UPDATED / CITY_OWNER_CHANGED / CITY_UPDATED /
  TURN_CHANGED / BATTLE_FINISHED`，全部登记在 `offs[]`，`dispose()` 统一退订。
- 状态变化**只打脏标**，由 `setTimeout(...,16)` 合并成一次 `flush`（没有变化就不会有后续调用，
  不是每帧轮询）。
- 去重：`dedupeKey` 相同且落在 60ms 窗口内的事件被丢弃（`forcedSyncs` 除外）。

### 2.5 UI 管理结构

```
#p1-ui (宿主, 已有)
 ├─ #p3-city / #p3-rail / #p3-detail      P3 城市管理（覆盖层）
 ├─ #p4-battle-hud / #p5-battle-ui        P4/P5 战斗表现
 └─ #p6-layer  pointer-events:none        P6 层
      ├─ #p6-toast      提示条（不阻断）
      ├─ #p6-modal-layer 模态框（可见时挂 data-p1-ui-block）
      └─ #p6-fatal      致命错误面板（hidden，出错才显示）
#p6-saves / #p6-hint / #p6-chip          工具栏与存档面板（DOM 在 index3d.html）
```

输入阻断由 `UIStack` 单点决定：`stack.push(id,{blocking})` → `input.setUIOpen(blocking)`。
引用计数保证「嵌套弹窗只阻断一次、最后一个关掉才恢复」。`input.stats.blocked/restored` 可在状态面板核对。

### 2.6 资源生命周期

- `AssetManager` 单例，同一个 `game.zip` 只解析一次；纹理/图集在场景 `enter()` 时复用。
- 场景实例复用（`SceneManager._instances`），反复切换不重建，因此不会累积 GPU 资源。
- 计时器统一经 `lifecycle.interval()` 登记（实测 2 个：`p6-city-watch`、`p6-save-panel`），
  `dispose()` 一次性清空。
- 实测泄漏判据（见 §5 测试 F）：反复切换后 `subscriptions 58→58`、`相机 3→3`、`DOM 495→495`、
  帧数单调增长（渲染循环仍在跑）。

## 3. 场景切换说明（交付物 2）

### 3.1 战略地图 → 城市管理（不切 Three 场景）

P3 的城市管理是 **HTML 覆盖层**，不是独立 3D 场景。原因：原版 `ka()` 协程横跨
「选城 → 菜单 → 指令 → 回选城」，若做成独立场景会把协程切断。

流程：
1. 玩家点城 → `MapInteraction.handleCityClick(cityId, {intent:'select'})` → 原版 `zs()` 收到输入协议，
   按自身规则返回该城（**不是** P6 直接改 `Dn`）。
2. 原版 `ka()` → `ei()` → 桥接 `$r()` 询问 `window.__SGBY_P3_HOST__`（仅当 `cityLoop===true`）。
3. P6 的 `watchCityOverlay()`（400ms 低频比对，不是每帧）发现界面已开 →
   `director.openCityOverlay(cityId)` 登记 + `captureWorldState('打开城市管理前')`。

### 3.2 城市管理 → 战略地图

1. 玩家点「返回」→ 原版 `ei()` 返回 255 → `ka()` 继续下一轮 `zs()`。
2. `watchCityOverlay()` 发现界面已关 → `director.closeCityOverlay()` → 视野/选中按开界面前保存的状态恢复。
3. 实测：关闭后原版必回 `zs()`，3D 地图可继续点击。

### 3.3 战略地图 → 战斗

1. 出征由原版 `hi()` 校验相邻关系，指令进 `g_OrderQueue`（`OrderId=27`）。
2. 原版 `wa()` 处理指令 → `Uo()` → 桥接通知 `__SGBY_P4_HOST__`，P4 装载真实战况。
3. P4 调 `director.enterBattle()`（或 `SceneDirector` 收到 `SCENE_CHANGED`）：
   - 进入前 `captureWorldState('离开 world -> battle')`——保存相机 target/zoom 与选中城；
   - `battleEnters++`；顺手 `uiStack.closeOwner('p6-battle')` 收起 P6 自己的弹窗（战斗输入不能被动遮挡）。

### 3.4 战斗 → 战略地图

1. 原版 `g_FgtOver != 0` → `Uo()` 返回 → P5 交出控制权 → P4 `exit()`。
2. `_applyTransition('battle','world')`：`battleExits++` → `restoreWorldState()`（相机/选中）→
   `queueMicrotask(resyncWorld)`（等 P4 的 `onExit` 走完再重建，避免「先显示旧数据再刷新」）。
3. `resyncWorld()` 按**最新 `Dn`** 全量刷新 38 城 + 38 面旗帜 + 清理失效选中。

### 3.5 防循环 / 防黑屏

- `_switching` 重入锁：并发切换第二发直接返回 `{ok:false, reason:'上一次场景切换尚未完成'}`。
- `_checkLoop()`：1s 内同目标超过 4 次 → 抛「疑似无限循环切换」，`stats.loops++`，场景不变。
- 非法目标（如 `world → world`）由 `SCENE_TRANSITIONS` 拒绝，**当前场景保持不变**（实测拒绝 1 次、
  场景仍是 `world`），不会出现黑屏。

## 4. 状态同步说明（交付物 3）

### 4.1 城市状态

- 数据源：`adapter.getCities()`（38 座，直接读 `Dn.g_Cities`）。
- 3D 表现：`scene.refreshCity(id)` 只改该城的字段/旗帜，不重建整图。
- 触发：`CITY_UPDATED` / `CITY_OWNER_CHANGED` → 打脏标 → 16ms 合并 → `sync.flush()`。
- 一致性检查：`cityRenderer.cities.length === 38` 且名称与 `Dn` 逐项相同；旗帜 `_owner` 必须等于 `ownerId`
  （最容易被漏刷的地方，因此单独检查）。

### 4.2 武将状态

- 数据源：`adapter.getCityOfficers(cityId)`（原版 `ss()` 口径）。
- 表现：城市面板「武将」页签（姓名 + 原版 13 列）；指令执行后武将离开队列会随 `OFFICER_UPDATED` 刷新。

### 4.3 势力（君主）状态

- 归属变化经 `CITY_OWNER_CHANGED` → 旗帜 `syncAll()` + 选中校验；君主切换（剧本/读档）由
  `TURN_CHANGED` 与 `GAME_STATE_UPDATED` 双路触发全量重建（`force` 同步）。

### 4.4 战斗结果

- 胜负**只**来自 `Dn.g_FgtOver`（1=我军胜 / 2=我军败），P4/P5/P6 都不做判定。
- 战斗结束 → `BATTLE_FINISHED` → 若 P4 已退出则 `resyncWorld('战斗结束(事件)')` 全量重建。
- 实测：战斗结束回到战略地图后 `active=false / scene=world / hud=false`，城市归属可继续读取。

### 4.5 回合状态

- `TURN_CHANGED` → `flush('turn')` + `savePresentation('turn')`（回合边界顺手落一份表现配置）。
- 回合推进本身完全由原版 `Io()`（回合开始）/`So()`（敌方阶段）决定，P6 不介入。

### 4.6 一致性检查（可观测的验收形式）

`StateSync.consistency()` 每次比对 6 类，返回 `{ok, mismatches[], detail}`，**只报告不修改**：

1. 3D 城市实例数 vs `Dn` 城市数（+ 名称逐项）
2. 旗帜归属 vs `ownerId`
3. 选中城市是否真实存在
4. 原版战斗态与当前场景是否自洽
5. 渲染循环是否仍在运行、渲染器是否失败
6. 事件订阅数是否比基线**下降**（下降=某场景没重建订阅）

## 5. 存档兼容报告（交付物 4）

### 5.1 原版存档格式（全部来自原版符号，未复制实现）

| 事实 | 值 | 原版出处 |
| --- | --- | --- |
| 文件头 | `[83,71,66,51]` = `"SGB3"` | `Rn` |
| 版本字节 | `4` | 头后第 5 字节 |
| key 规则 | `${prefix}${2*slot}.sav` / `+1.sav`，prefix 默认 `sgby.sango`（可被 URL `?save=` 改） | `jn(slot)` |
| 槽位数 | 3 | `jn` 取值域 |
| base 片长度 | `35 + 19*将 + 2*将 + 2*道具`（本资源包 = **4301 B**） | `Ae/Ie` 容量 |
| dyn 片长度 | `2035 + 37*城`（本资源包 = **3441 B**） | `Fe` 容量 |
| 写入 | `ac(slot)`，逐字段写、**非原子** | `ac` |
| 读取 | `oc(slot)`，逐字段覆盖 `Dn` | `oc` |
| 是否含战斗态 | **不含** | 字段表里没有 `g_FgtOver/g_GenPos` |

P6 **没有**新增任何存档字段、**没有**改 `Rn`/版本号、**没有**自己拼 key；`core.p6.save` 直接把
`jn/Jn/Hn/sc/ac/oc` 暴露出来给 `SaveManager` 调用。

### 5.2 兼容性处理

| 场景 | 处理 |
| --- | --- |
| 新游戏保存 | 直接 `ac(slot)`；实测 `base 4301 B / dyn 3441 B`，与容量公式一致（`sizeMatch=true`） |
| 读旧存档 | `oc(slot)` 前先 `inspect()`：`headerOk` + `version===4` + `sizeMatch` 才是 `compatible`；不满足会在面板上标注 |
| 战斗前 | 只能停战略阶段存（战斗态不入档）；实测「出征前」写入槽位 3 成功 |
| 战斗后 | 必须等原版走完 `wa()`/`Ma()` 回到 `ka()` 城市阶段再存，否则会存到半个指令队列 |
| 战斗中 | **拒绝**存档与读档，理由写进 `gate.reasons`（不含战斗态 / `Uo()` 正在跑，覆盖 `Dn` 会撕裂战况） |
| 指令上下文 | `window.__SGBY_CTX` 存在时**拒绝**（`Dn` 可能只更新了一半） |
| 读档后 | `oc()` → 原版 `qs(Dn.g_CityPos)` 重绘 2D → `adapter.sync({force:true})` → `director.afterLoad()`（清 UI 栈 → 关城市覆盖层 → 重建 38 城/38 旗 → 必要时切回 world → 恢复相机） |
| 读档失败 | 原版 `oc()` 非原子，返回 `partial:true` 并明确提示「建议重启页面」，绝不假装成功 |
| 3D 表现配置 | 独立键 `sgby3d.presentation.v1`，只存 `version/camera/ui/selection`；`auditPayload()` 结构性禁止 `city/officer/king/money/food/arms/belong/turn/year/month/sav` |

### 5.3 实测结果（浏览器）

- 槽位 key：`#1:sango0.sav+sango1.sav #2:sango2.sav+sango3.sav #3:sango4.sav+sango5.sav`（来自 `jn()`）。
- 战前存档：`190 年 · 君主 #5 / base 4301 B / dyn 3441 B`，`compatible=true`（旧档可继续读出）。
- 战后存档：`槽位 1 · base 4301 B / dyn 3441 B`，头 4 字节 `SGB3`、版本 `4`。
- 读档：`redrawn=true`（原版 2D 重绘）· 城市 38 座 / 旗帜 38 面重建 · 年份回到存档时点 `190`。
- 键空间：`.sav` 4 个（2 槽），`sgby3d.presentation.v1` 1 个，两者互不包含（`.sav` 里没有 `3d/presentation` 字样）。

## 8. 遗留问题（交付物 7）

### 8.1 自动化对局里「战败后重新进城」需要外部推动

- **现象**：战斗由原版规则提前结束（粮尽，`over=2`）后，原版要依次经过「战报 → `wa()` 指令处理 →
  `Ma()` 回合菜单 → 下一回合 `ka()`」才重新进入玩家城市阶段。自动化脚本必须「点掉提示框 / 补一次
  确认键 / 等到 `cityLoop===true`」才能继续点城市；否则点击城市只会走路、不开界面。
- **原因**：这是**原版正常流程**（`wa()` 里也有 `zs()` 选目标），不是缺陷。P3 的接管条件
  （`__sgbyP3Ask` 要求 `cityLoop===true`）刻意不接管 `wa()` 阶段的 `zs()`。
- **同源现象（本轮新发现）**：**本月已行动的城**被选中时，原版会弹一次提示（`Ms()`，`lastWidget=Ms`）
  然后**回到选城**，不会进 `ei()`/`$r()`，所以城市界面不开，`declines` 仍为 0。这不是 P6 的 bug，
  是原版「每城每回合一次」的规则；读档回到战前状态后，出征过的那座城在本回合已行动，因此第一次点它
  必然进不去。测试脚本的处理方式：**换一座己方城继续点**（`p6Cities` 候选表，最多 3 次），
  这与玩家行为一致。
- **影响范围**：只影响自动化脚本，玩家手动玩完全正常（玩家看到提示会换一座城或结束回合）。
- **是否影响正常游玩**：不影响。
- **建议处理方式**：P7 若要做「一键重开/连续自动对局」，把这套「战报→回合菜单」等待封装成
  `__P6__.advanceToCityPhase()` 调试入口，并在 adapter 上暴露「该城本回合是否已行动」的只读判定，
  脚本就不用靠试错。

### 8.2 存档面板不做「导入/导出文件」

- **现象**：只能读写浏览器 `localStorage` 的 3 个槽位，不能把 `.sav` 存成文件或从文件拖入。
- **原因**：任务书只要求「原版存档兼容」；`SaveManager.describe(slot)` 已给出只读描述，导入未实现。
- **影响范围**：跨设备迁移存档。
- **是否影响正常游玩**：不影响。
- **建议处理方式**：P7 用 `describe()` 的输出 + `localStorage` 原文做导出，导入前必须校验
  `headerOk/version/sizeMatch`，不匹配就拒绝（否则 `oc()` 非原子失败会留下半个状态）。

### 8.3 战斗态不入档带来的固有边界

- **现象**：战斗中不能存档，读档也必须在战略阶段。
- **原因**：原版存档字段表里没有战斗态（`g_FgtOver/g_GenPos` 等），这是原版设计。
- **影响范围**：战斗中途退出无法续战。
- **是否影响正常游玩**：不影响（与原版一致）。
- **建议处理方式**：如需「战斗中途续战」，必须另建独立存档通道（P6 明确不做，避免污染原版格式）。

### 8.4 城市场景（`city`）仍在场景表里但不进入

- **现象**：`SCENE_TRANSITIONS` 允许 `world → city`，但 P6 实际用 HTML 覆盖层，`CityScene` 不会被 `enter`。
- **原因**：P3 的实现方式（HTML 覆盖层 + 原版协程跨选城）决定不能切成独立 3D 场景。
- **影响范围**：无功能影响；只是场景表里保留了一条未使用的边。
- **是否影响正常游玩**：不影响。
- **建议处理方式**：P7 若真要做 3D 城市内部，需要先解决「`ka()` 协程跨阶段」问题（用状态机镜像而非切场景）。
